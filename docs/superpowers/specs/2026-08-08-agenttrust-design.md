# AgentTrust：智能体互信协议 —— 设计规格

- **日期**：2026-08-08
- **状态**：已获用户批准（五节设计全部确认）
- **项目代号**：AgentTrust（智能体互信协议）
- **最终目标**：上线一个开发者社区（B2D）+ 完成一篇顶会/期刊级别论文

## 1. 背景与愿景

智能体（AI Agent）时代到来，智能体将作为人类的"数字孪生"代替人类进行交易。类比：以物易物→线上支付（支付宝解决买卖双方信任）→智能体时代。智能体之间交易需要解决互信问题：如何保证没有"骗子智能体"？出现骗子智能体后如何追责？

**核心判断（调研验证）**：区块链智能合约可以解决智能体互信——行业正在按此方向收敛，最强证据为 **ERC-8004 "Trustless Agents"**（MetaMask/以太坊基金会/Google/Coinbase 提出，2026-01-29 以太坊主网上线），它提供身份/信誉/验证三注册表，明确声称设计动机是"A2A/MCP 不覆盖发现与信任"。本项目与其对齐而非另造标准，差异化在其未覆盖的"担保+信誉闭环"。

## 2. 调研结论摘要（依据见 papers/README.md，30 篇验证论文）

1. **通信双栈已成事实标准**：MCP（智能体↔工具）+ A2A（智能体↔智能体，Linux Foundation 托管，150+ 组织）
2. **纯声誉/纯声明不可靠**（提示注入、共谋、Sybil 实证；ERC-8004 信誉注册表 73.5% 评论者呈 Sybil 特征）→ 前沿共识：Proof（zk/TEE）+ Stake（质押惩罚）锚定高价值动作，声誉仅辅助
3. **"证明是智能体"无行业标准**（反向人证问题）——原始设计空间，MVP 暂不解决
4. **担保层主力机制**：escrow/HTLC + 质押 + 仲裁（Kleros/UMA）；去中心化保险（Nexus Mutual 式）只承保代码风险不承保行为风险，故本项目用"担保人质押金"模型而非保险池
5. **论文空白**：Schelling 点信誉社区 → 担保定价/争议裁决的闭环无人在做（Insured Agents 用 TEE 审计；2511.03434 只分类；UMA 止步预言机）
6. **商业教训**：先修路后造车必死（x402 交易量跌 92%）；信誉必须绑定资金（skin in the game）；先找真实付费场景

## 3. 定位与场景（已确认）

- **定位**：B2D 开发者基础设施——给智能体开发者发"执照+担保+信誉"，接入 MCP/A2A 生态
- **首个场景**：智能体间服务交易（A2A 服务市场：智能体互相买卖 API 调用/数据分析/任务外包）
- **上链程度**：全链上 EVM L2（Base，测试网起步）
- **资源约束**：在校生，一个学期（3-4 个月）完成，论文优先、MVP 可演示
- **论文目标**：顶会/期刊级别（完整形式化 + 仿真 + 实证）

## 4. 系统架构

```
┌───────────────────────── 社区前端（开发者门户） ─────────────────────────┐
│  注册智能体 · 发起交易 · 质押担保 · 查看信誉 · 参与争议投票（Schelling）    │
└──────────────┬──────────────────────────────────┬───────────────────────┘
               │ MCP/A2A 兼容 SDK（智能体通过工具调用协议）│
┌──────────────▼──────────────────────────────────▼───────────────────────┐
│                        EVM L2（Base，测试网起步）                        │
│                                                                          │
│  IdentityRegistry     GuaranteeEscrow         ReputationHub               │
│  身份注册表            担保托管合约            信誉中心                    │
│  · agent DID 注册      · 付款进 escrow         · EAS attestation 存证     │
│  · 人类-智能体绑定      · 担保人质押+保费        · 信誉分计算（链下算链上锚）│
│  · anti-Sybil 小额质押  · 交付确认自动释放        · Schelling 争议投票      │
│  · session key 限额     · 违约罚没/仲裁分支      · 信誉→保费定价输入        │
│                                                                          │
│  争议层：Kleros 集成（MVP：人工+LLM 辅助复核）                            │
└──────────────────────────────────────────────────────────────────────────┘
```

**关键设计决策**：
1. 与 ERC-8004 对齐（身份注册表接口语义），做其未覆盖的"担保+信誉闭环"
2. Base 首选（Coinbase 生态、gas 便宜、测试网免费；Kleros 在 Arbitrum，跨链仲裁接口成熟）
3. 担保人 = 平台核心经济角色（任何人可为卖方质押担保收保费，市场定价）
4. Schelling 投票只用于争议裁决（低频、高价值），控制 UX 复杂度与 Sybil 攻击面

## 5. 身份层 `IdentityRegistry`

**注册流程**：人类开发者连接钱包 → 注册智能体 → 铸造 Agent ID（ERC-721，对齐 ERC-8004 身份注册表语义）→ 记录责任主体 owner=开发者钱包 → 创建 AgentWallet（ERC-4337 克隆钱包）→ 初始化信誉档案。

- **Agent ID**：ERC-721 + DID document（did:ethr），元数据含名称/能力描述/MCP·A2A endpoint；可移植（换平台身份不丢）
- **责任绑定**：owner 即法律责任人（担保责任、违约追责落在真实主体——中国司法语境合规要求，见 §8）
- **AgentWallet**（ERC-4337，每智能体一个）：session key 授权给智能体执行；硬限额（单笔 ≤0.05 ETH、日累计 ≤0.1 ETH，参数化）；owner 持最高权限可随时冻结
- **anti-Sybil**：注册质押（测试网象征值），新智能体信誉=0，需担保人担保才能接高价值订单

## 6. 担保层 `GuaranteeEscrow`

**交易状态机**（每个状态带时间锁超时默认动作）：

```
CREATED ─买家付款─▶ FUNDED ─担保人质押─▶ GUARANTEED ─卖家交付声明─▶ DELIVERED
  │超时取消            │退款           │                            │
  └─── 买家确认 ──────────────▶ RELEASED（卖家收款，担保人拿回本金+保费）
  └─── 争议 ──────────────▶ DISPUTED ──仲裁裁决──▶ RESOLVED
        （冻结 escrow）         ├ 卖家胜诉：RELEASED
                               ├ 买家胜诉：全额退款 + 担保金罚没补偿买家
                               └ 部分胜诉：按裁决比例分配
```

- **担保人（Guarantor）**：任何人为卖方质押 `交易金额 × 覆盖率`（默认 100%），收保费
- **保费 = 担保人自主报价**（竞争市场；信誉做准入信号）——MVP 市场定价，论文版升级为信誉函数
- **违约罚没** = 担保人承担风险（"智能体保险"的诚实形态）
- **仲裁分支**：争议冻结资金 → 证据提交（交付哈希、对话日志摘要）→ 仲裁层裁决。MVP：平台人工+LLM 辅助复核；论文版：Kleros 集成 + Schelling 社区投票

## 7. 信誉层 `ReputationHub`（论文核心）

**Schelling 点信誉社区**：

```
争议发生（资金冻结在 escrow）
        ▼
社区投票（Schelling 协议）：
  任一信誉 ≥ 门槛的成员可发起争议案
  随机抽选 N 名陪审员（N≈7，质押门槛过滤 Sybil）
  每名陪审员质押 v 后投票：{支持卖家 / 支持买家 / 弃权}
        ▼
收敛判定：多数方获 ≥ 2/3 票数（参数化）→ 裁决成立
  与多数一致者：拿回质押 + 分得少数派罚没奖金（激励说真话）
  少数派：质押罚没，分给多数派
        ▼
闭环输出：
  ① 裁决 → escrow 释放/退款/罚没担保金
  ② 裁决 → EAS attestation（结果+票型）写入信誉档案
  ③ 信誉变化 → 影响担保准入与保费（定价输入）
```

**博弈论基础（论文形式化核心）**：
- Schelling 点博弈：独立投票时唯一一致收敛点 = 客观真实
- 激励相容：与多数一致率 > 50% 时诚实为占优策略（质押×(1-被罚概率)）
- 防 Sybil/共谋：质押成本 × 随机抽选；二次违规加大罚没；信誉越低质押要求越高
- 与 UMA/Kleros 的增量：裁决对象是"履约质量+责任判定"而非"事实断言"，且裁决直接驱动担保保费定价——"信誉→定价→担保→裁决→信誉"完整回路

**信誉档案**：每次交易/裁决 → EAS attestation（不可篡改、"警察证据"）；信誉分 = EigenTrust 式加权聚合（链下算、链上锚定）；多维档案（准时率/违约记录/争议胜诉率/担保人背书）；**禁止自评**。

> **无币化澄清**：MVP 阶段所有质押/罚没/保费使用测试网代币模拟机制（演示目的，无真实价值）；价值代币化路径（信誉分→价值积分→合规 token）属于海外合规架构下的长期方向（§8.4），不在 MVP 范围。

## 8. 合规设计（中国法律红线，硬约束）

1. **无币化**：社区 MVP 不发行任何代币/可交易凭证。积分/信誉分不可兑换、不可转让、无撮合（2017 年"94 公告"、2021 年十部门通知、2022 年三协会 NFT 倡议）
2. **责任归属**：智能体无民事主体资格（杭州互联网法院 2025 年判例）；担保/保证责任必须由真实主体（开发者/平台）依《民法典》承担——注册即绑定 owner，合约权限设计体现
3. **内容合规**：AI 生成内容按 2025 年《人工智能生成合成内容标识办法》可溯源
4. **长期 token 路径**：仅海外合规架构（香港 VASP 或境外实体 + 律师主导），境内不做
