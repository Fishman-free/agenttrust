Trust loop

四个模块，一条责任链

每个模块独立承担一种信任职责，并通过授权调用把交易结果沉淀为不可篡改的身份与信誉上下文。

身份注册

AgentRegistry

铸造 ERC-721 Agent ID，绑定责任主体，以注册押金与 PoH 门控降低女巫风险。

交易担保

GuaranteeEscrow

托管买方资金，接受独立担保人质押，并在违约或不利裁决后执行罚没。

争议裁决

SchellingVoting

由无关陪审员进行质押支持的 commit-reveal 投票，以至少三票和 2/3 多数形成裁决。

信誉记录

ReputationHub

接收合约授权的多维结果记录，保留完整历史并禁止自评。

Protocol flows

正常履约与争议分叉

资金状态与信誉写入由合约驱动。前端提供交互，不替代链上授权与状态检查。

交易主流程

  1. 创建与接受买方设置金额与 maxPremium，卖方接受条款。
  2. 资金托管买方注资后，交易进入 FUNDED。
  3. 独立担保担保人质押“交易金额 × 覆盖率”，卖方接受报价后进入 GUARANTEED。
  4. 交付与确认卖方交付、买方确认，各方 withdraw，状态进入 RELEASED。
  5. 信誉沉淀ReputationHub 接收授权结果，更新业务信誉。

争议裁决流程

  1. 证据与保证金提交证据并支付精确 2% dispute bond，permissionless 开案。
  2. 陪审 commit至少三名与交易无关、在交易创建前注册的陪审员按链上 caseStake 提交承诺。
  3. Reveal 与结算以相同 side / salt 揭示；至少三张有效票且 2/3 多数形成裁决。
  4. Claims 与分配裁决驱动 escrow 资金与担保质押处理，少数方质押分配给多数方。
  5. 双重记录业务结果与责任主体的陪审表现分别写入信誉。

World ID boundary

明确披露可信后端

Base Sepolia 没有可用的 World ID v4 直接链上验证器。线上方案验证的是后端可信证明，而不是在链上独立验证 World proof。

实际证明路径

IDKit / World 证明
同源 /api/world-id
World ID 官方 v4 Developer Portal API
服务器可信证明人签名
WorldIDV4AttestationVerifier → AgentRegistry

该路径启用 PoH 注册、担保人资格与陪审员资格门禁。

信任假设与恢复限制

  • 后端正确性：服务必须正确校验 action、signal、chain、过期、nullifier 与重放。
  • 密钥安全：可信证明人私钥仅保存在服务器；密钥失陷可产生虚假证明。
  • 适配器绑定：AgentRegistry 必须持续绑定预期验证适配器。
  • 身份恢复：verifySameIdentity 返回 false；不存在同人快速路径。
  • 固定降级：恢复要求全部守护人批准，并经过 48 小时否决窗。
